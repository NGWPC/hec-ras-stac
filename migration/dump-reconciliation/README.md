# dump-reconciliation

Pre-flight step for the HEC-RAS STAC migration. Reconciles two sources
of truth — Dewberry's raw S3 export and Dewberry's pgstac dump — and
emits a list of local items the migration should skip.

**Dewberry's pgstac dump is the final source of truth.** The destination
catalog mirrors what Dewberry publishes; anything not in the dump does
not migrate.

## Inputs

1. **Raw S3 export at `s3://fimc-data/dewberry-stac/`** — Dewberry's
   unpruned working files. Synced to local by
   `migration/sync_items.py`. ~178,826 item JSONs.
2. **pgstac dump** — Dewberry's curated published catalog, handed to
   us as a `.dump` file (PostgreSQL custom format). ~158k items across
   ~1,140 collections.

The dump represents Dewberry's pruned view; the S3 export is a superset
that includes superseded re-runs, name-colliding duplicates, and items
absent from the published catalog. The drop list reconciles them.

## Outputs

The three files consumed by the migration pipeline (`drop_list.txt`, `collection_overrides.tsv`,
`id_rewrites.tsv`) have been promoted to `migration/` and committed there. The remaining files
below stay in `outputs/` (gitignored) as local audit trail only.

All generated by `build_drop_list.py`:

| File | Description |
|---|---|
| `dump_items.tsv` | One row per dump item: `id`, `collection`, `source_hash`. Tabular form of the dump's published view. |
| `local_items.tsv` | One row per local item: `id`, `collection`, `source_hash`, `rel_path` (relative to the migration working dir). Tabular form of the S3 export. |
| `drop_classification.tsv` | One row per local item with its bucket, decision, override collection, and id rewrite (if any). Audit trail. |
| `drop_list.txt` | Rel-paths to skip during migration. Consumed by `rewrite_hrefs.py`. |
| `collection_overrides.tsv` | `rel_path → override_collection` map for bucket-D items. Consumed by `rewrite_hrefs.py` to assign a collection when the local JSON has `collection: null`. |
| `id_rewrites.tsv` | `rel_path → (local_id, dump_id)` map for items where the dump published a `_N` suffixed id. Consumed by `rewrite_hrefs.py` to set the item's `id` field to the dump's canonical value. |
| `verify_assets_failures.tsv` | Items whose source assets returned 404 on S3 (produced by `verify_assets.py`). Audit trail only — does not mutate `drop_list.txt`. |

## Classification buckets

Every local item is classified against the dump using
`(id, collection, source_hash)` and per-asset MD5 e_tags. Eight buckets;
five drop, three migrate:

| Bucket | Description | Decision |
|---|---|---|
| **A** | Exact match: `(id, collection, hash)` aligns with dump | **MIGRATE** |
| **B1** | Local catalogued, dump has same id under different collection with matching e_tags → same model, different name | **DROP** |
| **B2a** | Local `mip_no_crs`, dump has id under a real collection with different files → dump's corrected version supersedes ours | **DROP** |
| **B2b** | Local real-collection, dump has same id under a *different* real collection with no e_tag overlap → independent models sharing a name | **KEEP** |
| **C** | Local catalogued, id absent from dump entirely | **DROP** |
| **D** | Local uncatalogued, exact `(id, hash)` match in dump → dump publishes it under a real collection; local copy is the same files, just missing the `collection` field in the S3 export | **MIGRATE** with collection override |
| **E** | Local uncatalogued, id in dump under a different hash | **DROP** (superseded) |
| **F** | Local uncatalogued, id absent from dump entirely | **DROP** (genuine orphan; dump didn't publish) |

Bucket D's collection override is emitted to
`outputs/collection_overrides.tsv`. `rewrite_hrefs.py` loads it and sets
the item's `collection` field from the override when the local JSON
has `collection: null`. Without this, ~2,264 items including the
entire `ohio_rfc` collection would orphan at the destination.

## Scripts

| Script | Role |
|---|---|
| `restore_dump.sh` | Starts a local Docker pgstac container (`dewberry-pgstac-probe` on `localhost:5433`), restores the dump, leaves it running for the builder to query. |
| `build_drop_list.py` | The reconciler. Walks the local working dir, queries the restored dump, classifies every item into one of the eight buckets, emits `dump_items.tsv`, `local_items.tsv`, `drop_classification.tsv`, `drop_list.txt`, `collection_overrides.tsv`, and `id_rewrites.tsv`. |
| `patch_classification.py` | One-shot offline patch for the suffix-mismatch bug. Re-classifies the existing TSV outputs using only `dump_items.tsv` (no live DB). Only needed if `build_drop_list.py` was run before the suffix-match fix was added. |
| `verify_coverage.py` | Pre-migration coverage validator. Cross-checks the drop-list's expected survivor set against the dump's published set. Exit 0 = clean; exit 1 = discrepancy. Run after `build_drop_list.py`, before `migrate.py`. No external dependencies. |
| `verify_assets.py` | S3 health pre-flight. After `build_drop_list.py` emits `drop_list.txt`, this HEADs one representative asset per surviving item against `fimc-data`. Any 404s are logged to `verify_assets_failures.tsv` for review — report-only, does not mutate `drop_list.txt`. |

## End-to-end reproducibility

The full pipeline, from scratch:

```bash
# Prerequisites:
#   - AWS profile with read on s3://fimc-data/dewberry-stac
#   - Docker available locally
#   - psycopg2-binary and boto3 installed (pip install)

# 1. Sync the raw S3 export to local (~10-30 min at full scale).
cd migration
python3 sync_items.py --source-profile <profile> --whole-tree
# → ~178k JSONs at ~/ras-stac-migration/items/<prefix>/<hash>/<id>.json

# 2. Restore the pgstac dump into local Docker (~5 min first boot).
cd dump-reconciliation
./restore_dump.sh /path/to/<dump>.dump
# → dewberry-pgstac-probe container on localhost:5433

# 3. Build the drop list (~2 min).
python3 build_drop_list.py
# → outputs/dump_items.tsv
#   outputs/local_items.tsv
#   outputs/drop_classification.tsv
#   outputs/drop_list.txt
#   outputs/collection_overrides.tsv
#   outputs/id_rewrites.tsv

# 3.5. Apply the suffix-mismatch patch (offline, <1 sec).
#   NOTE: only needed if build_drop_list.py was run before the suffix-match
#   fix was added. The current version of build_drop_list.py includes the
#   suffix-match logic natively — skip this step on a fresh run.
#   The committed outputs (drop_list.txt, collection_overrides.tsv,
#   id_rewrites.tsv) were produced by running this patch on an earlier
#   build_drop_list.py output.
# python3 patch_classification.py
# → outputs/drop_classification.tsv  (updated)
#   outputs/drop_list.txt            (updated)
#   outputs/id_rewrites.tsv          (updated — 454 suffix-mismatch rewrites)

# 3.6. Verify the drop-list survivor set matches the dump (offline, <1 sec).
python3 verify_coverage.py
# → PASS: missing=1 (known dump-duplicate W/W_1), real_gaps=0, extras=0
# → FAIL: exit 1 if any dump item is missing from the expected survivor set

# 4. Verify source assets still exist on Dewberry's S3 (~1 min).
python3 verify_assets.py --source-profile <profile>
# → outputs/verify_assets_failures.tsv (audit trail; does not mutate drop_list.txt)
# → exit 1 if any failures; review before proceeding

# 5. Run the migration; rewrite_hrefs.py automatically loads drop_list.txt
#    and skips matching items during the per-item walk.
cd ..
python migrate.py

# 6. Teardown when done.
docker rm -f dewberry-pgstac-probe
```

## What landed in the latest run

178,826 local items classified against a 158,177-item dump:

```
A     155,875  MIGRATE (exact match or dump-suffix match)
B1          0  (absorbed into A — same model, dump added _N suffix)
B2a         0  (absorbed into A — same model, dump added _N suffix)
B2b         0  (absorbed into A — same model, dump added _N suffix)
C           0  (absorbed into A — same model, dump added _N suffix)
D       2,303  MIGRATE with collection override from dump
               (includes 39 uncatalogued suffix-match items)
E      20,516  DROP (uncatalogued superseded)
F         132  DROP (uncatalogued orphan, never published)
TOTAL 178,826

MIGRATE: 158,178 items (A + D)
DROP:     20,648 items
```

Note: the B1/B2a/B2b/C buckets are zero because the dump applies `_N` numeric
suffixes to resolve within-collection id duplicates. The S3 export stores the
same items without the suffix, so the initial reconciliation mis-classified 415
catalogued items as non-A. A post-classification patch (`patch_classification.py`)
and the updated `build_drop_list.py` correct this by matching on `(hash, collection)`
in addition to exact `(id, collection, hash)`.

`id_rewrites.tsv` records the 454 items whose `id` must be rewritten from the
local unsuffixed value to the dump's canonical suffixed value at migration time.
`rewrite_hrefs.py` applies these rewrites.

`hec_ras_uncatalogued` no longer exists as a destination collection —
every surviving item has a real `collection` value.

## One side-effect worth knowing

Bucket B2b items create cross-collection id duplicates in the
destination — the same `id` (e.g. `Sand_Creek`, `SPRING_CREEK`,
`CEDAR_CREEK`) appears in multiple collections. This is correct STAC
behavior (`id` is unique only within a collection), but consumers
querying by `id` alone will get multiple hits. Query by
`(collection, id)` for unambiguous results.

## Re-running against an updated dump

When Dewberry publishes a new dump:

1. Re-sync the S3 export if needed (`sync_items.py` is idempotent).
2. `./restore_dump.sh /path/to/<new>.dump` — script tears down the prior
   container and restores the new dump.
3. `python3 build_drop_list.py` — emits fresh outputs. Sort and diff
   the previous `drop_list.txt` against the new one to see what
   changed.
4. `python3 verify_assets.py` — re-runs the asset existence sweep.
5. Re-run `migrate.py`.

Outputs are deterministic for a fixed `(S3 export, dump)` pair —
re-running `build_drop_list.py` without changing inputs produces a
byte-identical `drop_list.txt` (modulo line ordering, which is
sorted in the script's output).
